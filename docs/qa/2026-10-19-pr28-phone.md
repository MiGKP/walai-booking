# PR 28 integration and profile phone validation

## Resulting behavior

- Profile updates reject a phone already used by another member or staff account with HTTP 409 and a Thai message. The current account is excluded, empty phones remain allowed, and punctuation is ignored when comparing numbers.
- Profile phone updates use a transaction and advisory lock so concurrent profile changes cannot claim the same number.
- Existing phone duplicates are not rewritten. This change does not add a database constraint or change registration/staff-creation rules.
- Staff OTP recovery remains scoped by `account_type=staff` and requires an active staff account.

## PR integration decisions

- Retain the teammate's room/boat filter controls, sorting, pagination, sticky actions, statistics presentation, CSV export, registration avatar upload and updated check-in/profile presentation.
- Retain the current role-scoped statistics service, correct database column names, promotion revenue allocation, shared boat inventory and review eligibility guards.
- Retain admin-only promotion writes. Room staff can read promotions; the existing UI explicitly uses `canEdit = role === 'admin'`.
- Update the two new promotion test expectations to distinguish future and disabled promotions from expired ones.

## Limits

Phone uniqueness is checked on the profile-update path, not enforced globally by a schema constraint. Other account-creation/admin-edit paths require a separate change if global uniqueness is desired. Formatting comparison strips punctuation; country-code aliases are not canonicalized.
