### TypeScript 7 compatibility exception

TypeScript 7.0.2 was tested before selecting 6.0.3. The TypeScript 7 CLI compiled the backend, but existing JavaScript compiler API consumers failed:

- ts-node encountered an undefined `ts.sys.fileExists`.
- typescript-eslint encountered an undefined `ts.Extension.Cjs`.
- The installed Next.js tooling still consumes the previous compiler API; the current typescript-eslint peer range is `>=4.8.4 <6.1.0`.

Both manifests therefore use `~6.0.3`, the latest compatible release tested in this toolchain. The final registry update check reported only TypeScript as newer. Type checking and lint rules were not disabled, and installed package sources were not patched to bypass these errors.

## Compatibility changes

### Backend

- Kept the extended query parser and added `preserveRequestQuery` before the routes. Express 5 exposes `req.query` through a getter; retaining one request-local object preserves express-validator sanitization. An HTTP regression first reproduced loss of trimmed search text, then passed after the fix. Duplicate pagination and array search input are still rejected.
- Narrowed payment route IDs before calling `split`, matching the Express 5 parameter types and returning a 400 response for invalid IDs.
- Moved the Prisma datasource URL into `prisma.config.ts`, following Prisma 7's configuration format. The database models were not changed or migrated.
- Set TypeScript module resolution to Node16 while preserving the backend CommonJS runtime.
- Added regressions for mounting all API routers, unauthenticated route rejection, query validation, and compatibility with a TEST bcrypt hash generated by bcryptjs 2.4.3.

References: [Express 5 migration guide](https://expressjs.com/en/guide/migrating-5/), [Prisma configuration reference](https://www.prisma.io/docs/orm/v7/reference/prisma-config-reference).

### Frontend

- Migrated to the official Tailwind 4 PostCSS plugin and CSS imports. Retained the existing brand tokens and added compatibility defaults for borders, placeholders, rings, and cursor behavior.
- Updated renamed Tailwind utilities to preserve their previous visual scale. Most changed frontend files contain these class migrations, rather than changes to booking behavior.
- Replaced the removed Lucide Facebook brand export with React Simple Icons, preserving the existing displayed icon and its styling.
- Fixed 21 errors surfaced by the latest lint rules: function declaration ordering, render-time ref writes, and a filter component recreated during render. No lint rules were turned off.
- Retained the existing frontend `.npmrc` installation convention.

Tailwind 4 raises the browser compatibility floor to Safari 16.4, Chrome 111, and Firefox 128. Older browsers were not tested. See the [official upgrade guide](https://tailwindcss.com/docs/upgrade-guide).

## Security audit

Counts represent affected dependency packages, not independently reproduced attacks.

| Package | All dependencies | Production dependencies |
| --- | ---: | ---: |
| Backend | 0 | 0 |
| Frontend | 5 high | 0 |

The frontend's five reports trace to one unpatched `braces` issue through `micromatch`, `fast-glob`, `@next/eslint-plugin-next`, and `eslint-config-next`. Tailwind 4 removed the previous Tailwind/chokidar paths from the affected chain. The installed latest `braces` 3.0.3 remains affected. The audit's proposed ESLint config downgrade is not an appropriate substitute for a compatible upstream patch.

These are development tooling dependencies. Production-only audit success does not establish that every application path is secure. No advisory was suppressed and no audit threshold was weakened. See the [upstream advisory](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm).
